# 项目简报（研究版）

日期：2026-10-16。状态：研究工作已获授权；应用实现范围尚待确认。

## 问题与目标用户

用户在现场对话中容易遗漏条件变化、历史承诺和需要追问的信息。DecisionFlow 研究如何结合上下文和背景资料提供及时、有依据、可追问的辅助。

首位使用者为项目作者本人。项目主要用于求职展示，具体目标岗位尚未确定，不据此擅自扩大技术范围。

## 主要用例

1. 持续听取一段会议或谈判，保留可回溯的发言记录。
2. 用户通过语音或文字追问当前话题，系统结合上下文回答。
3. 识别重要变化，生成包含依据与建议追问的提醒。
4. 调用用户明确提供的资料和历史记录，支持纠正与删除。

## 候选最小验证范围

先使用虚构中文对话回放验证算法，再验证麦克风实时输入。研究三种参与策略：仅记录、征询后展开、主动提醒。分析结果需要支持继续追问。

候选能力：转写事件流、会议状态、资料检索、按需专项分析、证据复核、提醒去重与输出控制。具体实现范围须在研究审阅后确认。

## 排除范围

首轮不包含硬件、商业收费、多租户企业平台、自动执行经营决定、全行业专家能力、未经验证的情绪判断和自动训练个人专属模型。个人微信接入单独研究，不假定存在稳定接口。

## 产品形态与商业模式

优先考虑本地运行的个人对话演示系统，候选为浏览器界面与本地后端。当前不商业化，求职展示采用虚构资料和可重复的演示脚本。

## 技术方向（候选）

Python/FastAPI、TypeScript/React、WebSocket；用显式状态图组织分析，评估 LangGraph 的适用性。数据库和向量检索按实际规模选择，不为个人演示预先引入分布式系统。语音识别、语言模型和语音合成通过适配层接入，供应商与版本未定。

## 数据与安全

音频、转写和衍生记忆关联会话与来源；明确录音状态与外部处理范围；密钥保存在服务端环境或本地凭据配置，不写入仓库。默认用虚构材料研究，真实资料须显式选择后才外发。检索资料和转写均按不可信输入处理，不能改变系统权限或通知接收者。删除需覆盖记忆与索引。

## 里程碑

- M0：完成证据表、候选架构和验证计划。
- M1：确认研究结论、实验范围、模型处理边界和预算后，建立离线回放实验。
- M2：以对照实验确定 Agent 分工与介入策略。
- M3：确认软件范围后接入实时语音和界面，核查通知渠道。
- M4：发布可复现的演示、测量结果和面试说明。

时间和预算尚未约定，不给出未经评估的工期。个人开发维护为候选假设；并发先限定单会话。失败应可重放定位，不依靠人工持续维护演示。

## 验收与成功标准

研究阶段：每个产品判断可追溯，推断不冒充事实；架构能逐步解释演示行为，并给出替代解释与实验。

实验阶段：比较单模型与多 Agent、无记忆与有记忆、单次检测与两阶段检测；统计提醒准确率、漏报、重复、证据正确率、延迟和成本。阈值在建立基线后确认，不能预写成绩。

## 风险与未决事项

演示可能经过剪辑；公开资料型号与版本不同；错误转写、缺失背景和多个 Agent 的共同偏差可能导致误判。长期记忆可能把推测写成事实，提醒可能过时或泄露信息。

实现前仍需确定：目标岗位、平台与操作系统、首个验证场景、供应商与数据外发、预算与时限、通知策略。当前继续独立研究，不以这些缺口阻止证据整理。
